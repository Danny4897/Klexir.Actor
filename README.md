# Klexir.Actor

Channel-backed actor primitives for Klexir. Each actor mailbox guarantees serialized state transitions. `ActorRegistry` creates and tracks actors by id, `Actor<TMessage,TState>` exposes `PreStartAsync`/`PostStopAsync` lifecycle hooks, and `SupervisionOptions` drives a OneForOne restart strategy (`RecoverAsync` computes the resume state after a handled failure; the mailbox stops once the restart budget is exhausted). `ActorScheduler` delivers a message once after a delay or repeatedly on an interval (`PeriodicTimer`-backed), returning a cancellable schedule id; disposing the scheduler stops everything still pending. `AskAsync` sends a message and returns the state produced by processing it (or throws on handler failure, restart exhaustion, or timeout); pending asks are faulted rather than left hanging if the actor stops before reaching them.

`Actor<TMessage,TState>.ExtractDomainEvents(previous, next)` lets an actor emit domain events after a successful state transition; `InMemoryActorRef`'s optional `IDomainEventPublisher` publishes each in order (a publish failure fails the message like any other handler error). `IDomainEventPublisher` is Actor's own minimal contract — plain `object`, no dependency on Klexir.EventFlow — so an application wires it to a real event bus with a small adapter of its own rather than this repo taking on a cross-repo package dependency.

Distributed actors (location transparency) are planned next.
